# Проверки и приёмка

[Содержание](index.md)

## Автоматические проверки

Из корня проекта:

```sh
pnpm check:i18n
pnpm lint
pnpm exec next typegen
pnpm exec tsc --noEmit
pnpm build
```

`next typegen` нужен на чистом checkout перед отдельным `tsc`: PageProps и
LayoutProps генерируются Next.js. Сборка тоже генерирует типы и проверяет TypeScript.
`pnpm build` повторно запускает `check:i18n`, поскольку проверка включена в script.

Проверка словарей использует только стандартные модули Node.js. Она проверяет:

- Совпадение ключей объектов, включая отсутствие лишних ключей.
- Совпадение типов и длины массивов.
- Непустые строковые значения в обоих языках.

Она не проверяет смысл перевода, соответствие цен карточкам, контраст, SEO-домен
и работоспособность контакта. ESLint и TypeScript также не заменяют браузерную проверку.
Постоянного unit/E2E test runner и команды `pnpm test` сейчас нет.

## Production smoke test

Собери приложение и запусти в отдельном терминале:

```sh
pnpm build
pnpm start --port 3107
```

Затем проверь ответы:

```sh
curl -I 'http://localhost:3107/?source=test'
curl -I http://localhost:3107/ru
curl -I http://localhost:3107/en
curl -I http://localhost:3107/de
curl -I http://localhost:3107/en/missing
```

Ожидается: 307 с `Location`, разрешающимся в `/ru?source=test`; затем 200, 200,
404 и 404. Location может быть относительным. Proxy работает только для `/`.

Проверь HTML или DOM браузера для каждой локали:

| Что | Ожидание |
| --- | --- |
| Корневой элемент | `<html lang="ru">` или `<html lang="en">` |
| Первый заголовок | Текст соответствующего языка |
| Title и description | Перевод из `metadata` |
| Canonical | Production-origin + текущая локаль |
| Hreflang | RU, EN и x-default |
| Open Graph | Переведённые title/description и правильный URL |
| Цены | 800 / 1500 / 3000 RSD с разделителями выбранной локали |

Если `SITE_URL` не установлен локально, метаданные используют порт 3000 даже при
запуске smoke-сервера на 3107. Это заданный fallback, а не ошибка сервера.

## Браузерный сценарий локализации

1. Открой `/ru?source=test#services` и дождись загрузки страницы.
2. Раскрой языковое меню, выбери English.
3. Проверь адрес `/en?source=test#services`, английский контент и активный EN.
4. Переключись обратно: ожидается `/ru?source=test#services` и русский контент.
5. Перейди по логотипу и пунктам навигации, раскрой FAQ.
6. Проверь отсутствие runtime/hydration ошибок в консоли.
7. Повтори на ширине 360 px и desktop; проверь, что шапка не выходит за viewport.
8. Проверь меню и FAQ клавиатурой, а также контактную ссылку.

Ранее такой сценарий выполнялся вручную через временный Playwright-инструмент.
Он не установлен в проекте и не запускается автоматически в CI. При добавлении
постоянного E2E-набора потребуется отдельная зависимость, установка браузера и
соответствующие системные библиотеки.

## Изменения документации

Для изменений только Markdown достаточно проверить существование относительных
ссылок и упомянутых файлов, соответствие команд `package.json`, сохранность
служебного блока Next.js в AGENTS.md и `git diff --check`.

При отчёте отделяй выполненные проверки от рекомендуемых и не объявляй браузерные
проверки выполненными только на основании успешной сборки.
